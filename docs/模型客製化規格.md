## 1. 名詞

| 名詞 | 意思 |
|---|---|
| 模型(model) | 一份 JSON:面向權重、短期門檻、指標清單(每個指標的取值、打分、權重)。決定「分數怎麼算」 |
| 出廠模型 | repo 內 `lab/models/jw-mf-2.0.json`,內容等於現行 JW-MF v2.0-dev |
| 我的模型 | 使用者存在 `private/models/<id>.json`,不進 git |
| 模型族(lineage) | 同一個 `family_id` 的所有版本。「試了幾次」、holdout 都以模型族計 |
| 評分雜湊(score hash) | 對影響分數的欄位(§2 標 ★)**加上** `model_params.json` 中影響評分的欄位(`valuation`、`method_weights`、`validated_pillars`、`cross_sectional_scoring`、`tw_industry_neutral_valuation`、`tw_chips_history`、`tw_st_drop_momentum`、`us_quarterly_ttm`、`decision_rules`)做正規化 JSON 的 SHA-256 前 16 碼;改名稱、說明不改雜湊。參數開關改變時雜湊跟著變,「試了幾次」才不會失真 |
| 基礎變數 | 平台算好的原始值(例:`roe`、`revenue_yoy`),運算式只能用這些 |

## 2. 模型檔格式(`h0-model/1`)

```json
{
  "schema": "h0-model/1",
  "id": "my-quality-tilt",
  "family_id": "my-quality-tilt",
  "name": "我的品質加重版",
  "based_on": "jw-mf-2.0@<score hash>",
  "created": "2026-11-02",
  "notes": "",
  "pillar_weights": {"long_term": {...}, "short_term_tw": {...}, "short_term_us": {...}},
  "short_term_thresholds": {"bullish": 62, "bearish": 42},
  "metrics": [
    {"key": "roic", "pillar": "quality", "applies": "non_financial", "market": "all",
     "label": "ROIC 投入資本報酬率", "value": {"var": "roic"},
     "score": {"type": "linear", "bad": 0.0, "good": 0.25}, "weight": 3,
     "peer_blend": null, "enabled": true, "fmt": "pct", "note": "..."}
  ]
}
```

★ 影響分數的欄位:`pillar_weights`、`short_term_thresholds`、`metrics[*]` 的 `key / pillar / applies / market / value / score / weight / peer_blend / enabled`。

### 2.1 指標欄位

| 欄位 | 值 | 說明 |
|---|---|---|
| `pillar` | quality、growth、valuation、health、momentum、flows、revisions、sentiment | 面向(regime 大盤環境不是指標清單,沿用 `lab/analysis/regime.py`) |
| `applies` | `all`、`non_financial`、`financial` | 對應現行 `is_fin` 分支 |
| `market` | `all`、`TW`、`US` | 對應現行台股 / 美股分支(籌碼) |
| `value` | `{"var": "<基礎變數>"}` 或 `{"expr": "<運算式>"}` | 出廠指標用 `var`;自訂指標用 `expr` |
| `score` | 見 §2.2 | 原始值 → 0–100 |
| `weight` | ≥ 0 的數字 | 面向內權重;0 等於關閉但保留 |
| `peer_blend` | `null` 或 `{"peer_var": "...", "abs_weight": 0.6, "higher_better": true}` | 同業百分位混合(現行絕對 60% + 相對 40%);只有網站有同業資料 |
| `enabled` | true / false | 關閉時不計分、不計入覆蓋率 |
| `requires` | `null` 或基礎變數名 | 該變數為假值(None、0、False)時**不加這一項**(不進覆蓋率分母)。例:月營收三項、beneish、insider、rating_net、技術動能(`tech_available`) |
| `gate` | `null` 或 `{"var": "...", "min": n}` | 項目照樣加入,但 var < min 時分數為 None(「加了但不可得」,進覆蓋率分母)。例:news7 `{"var": "news_d7_n", "min": 3}` |
| `label` / `fmt` / `note` | 字串 | 介面用;`label` 可含 `{yoy_basis}` 這類範本,由 engine 代入 |

**engine 輸出**:每個面向輸出的 items 結構與現行 `Pillar.add` 完全相同(`key / label / value / score / abs_score / peer_pct / weight / fmt / note / available`),項目分數先 `round(·, 1)` 再加權,面向內依 `metrics` 陣列順序加總(浮點加總順序要和現行一致)。`backtest.py` 的 `_items`、`backtest_pit.cross_sectional_rescore` 都依賴這個結構。

**權重 0**:某面向所有可用項目的權重總和為 0 時,該面向分數為 None(現行程式會除以 0,只是權重都 > 0 所以沒發生)。

### 2.2 打分函數(`score.type`)

| type | 參數 | 公式 | 使用者可改 |
|---|---|---|---|
| `linear` | `bad`、`good` | 現行 `lin()`:線性內插,夾在 0–100;`bad > good` 代表越小越好;`bad == good` 回傳 50 | ✅ |
| `peak` | `center`、`slope` | `max(0, 100 − abs(x − center) × slope)`(現行 RSI:58、2.5) | ✅ |
| `map` | `table`(值 → 分數) | 類別值查表(現行趨勢狀態 −2..2) | ✅ |
| `builtin` | `fn` | 規則較複雜、寫在程式裡的打分:`mr_record`、`net_debt_ebitda`(`net_debt < 0` 時給 100,即使比值本身是 None 也算可用;否則 lin(4,0))、`beneish`、`insider`、`margin_weight`(融資占股本 < 0.5% 時權重 × 0.3;調整後的權重同時進覆蓋率分母) | 只能改權重或關閉 |

`peer_blend`:同業有效值 ≥ 4 才算百分位(`peer_percentile`),不足時 `peer_pct` 為 None,只用絕對分數。

自訂指標(`expr`)只能用 `linear`、`peak`、`map`。

**現行的特殊取值,一律在基礎變數層算好**(engine 與運算式不重做),以保證逐位元相同:
- `eps_cagr_eff` = `eps_cagr_3y or ni_cagr_3y`(**真值**語意:0.0 也會改取 ni,和 `coalesce` 不同)
- `fpe_rel_peers` = `forward_pe ÷ 同業 forward_pe 中位數`;同業先濾 `0 < x < 200`、數量 ≥ 3,且自己的 forward_pe 為真值才算,否則 None。這一項**永遠加入**,算不出來就是不可得
- `rating_net` = `up − down + 0.5 × (pt_raises − pt_lowers)`;`equity_assets` = `1 − liabilities_to_assets`

## 3. 運算式語言(層級 C)

### 3.1 語法
- 用標準函式庫 `ast.parse(..., mode="eval")` 解析,**白名單**以外的節點一律拒絕(不用 `eval`、不裝新套件)。
- 允許:數字、基礎變數名、`+ − × ÷`、`**`(指數限 −4 到 4)、一元負號、比較(`< <= > >= == !=`)、`and / or / not`、條件式 `a if 條件 else b`、白名單函式呼叫。
- 拒絕:屬性存取(`.`)、索引(`[]`)、字串、lambda、推導式、賦值、任何不在白名單的名稱。長度上限 500 字元、節點上限 200。
- 任何輸入是 `None` → 結果 `None`(該指標「不可得」,和現行一致);除以 0 → `None`。

### 3.2 白名單函式(第一版)

| 函式 | 說明 |
|---|---|
| `abs(x)`、`min(a, b, ...)`、`max(a, b, ...)`、`log(x)`(x ≤ 0 → None)、`sqrt(x)` | 純量運算 |
| `clip(x, lo, hi)` | 夾在區間內 |
| `safe_div(a, b)` | b 為 0 或 None → None |
| `coalesce(a, b, ...)` | 第一個不是 None 的值 |

時間序列函式(`ma(close, 200)` 這類)**第一版不做**:需要讓運算式直接讀價格序列,防洩漏測試範圍變大。第一版只開放已經由 PIT 算好的純量基礎變數(包含 `vs_ma200`、`mom_12_1` 等技術面變數)。之後要加,另外寫規格。

### 3.3 防洩漏
- 運算式只能讀基礎變數;基礎變數在網站由報告流程算、在回測由 `PITStore.as_of(d)` 算,**運算式本身碰不到任何資料來源**,洩漏只可能出在基礎變數層。
- 每個基礎變數在 M4 的原始值快取裡,用 `lab/pit/tamper.py` 做竄改測試(竄改判斷日以後的資料,值不得改變)。
- 自訂指標存檔時,自動在 3 個隨機判斷日跑一次竄改測試(M5)。**M5 實作改成單元測試**(`tests/test_model_honesty.py::test_custom_metric_tamper`):自訂指標只能讀同一筆判斷的基礎變數,基礎變數本身由已經有竄改測試的 PIT 管線算出;所以改掉某天以後的基礎變數,之前每一筆的分數都不變。存檔時對真實資料跑竄改測試要重建 PIT 情境、太慢,先不做。

### 3.4 基礎變數
- 清單 = §8 所有出廠指標的取值變數,外加 `close`(判斷日收盤價)、`market_cap`、`is_financial`(0/1),以及打分要用的輔助變數:`net_debt`、`margin_to_shares`、`beneish_flag`、`beneish_high_growth_caveat`、`insider_buy_count_6m`、`insider_sell_value_6m`、`news_d7_n`、`news_d30_n`、`mr_record_high`、`mr_record_same_month`、`tech_available`、`yoy_basis`(標籤用字串),以及同業百分位(`peer_pct_<指標>`,只有網站有)。
- `regime` 大盤環境分數也是基礎變數(短期分數有 10% 權重)。
- 每個變數標可得性:**網站** / **回測台股** / **回測美股**。回測沒有的變數(分析師預估、同業、新聞情緒、美股內部人等)寫在自訂指標裡 → 該模型的回測自動排除這個指標,並標示「此指標無法回測」。
- 變數清單、中文名稱、單位由 `lab/metric_dictionary.py` 產生,前端與 AI 都讀同一份。

## 4. 誠實驗證

### 4.1 試了幾次
- 每次對**新的評分雜湊**跑回測,模型族的計數 + 1;同一個雜湊重跑不加。
- 記在 `private/models/trials.jsonl`(模型族、評分雜湊、時間、開發集主要指標)。
- 使用者模型的回測呼叫 `evaluate.py` 時,登記簿一律指到 `private/models/experiments.jsonl`(`INVEST_LAB_REGISTRY` 機制),**不寫進主登記簿** `data/research/experiments.jsonl`,以免汙染出廠模型的計次與 Holm。
- 畫面固定顯示:「這個模型族試了 N 個設定」。N ≥ 2 時,p 值用 Bonferroni 校正(p × N,上限 1),並說明「試越多次,越容易碰巧找到好看的結果」。
- 從出廠模型複製出來的新模型族,N 從 1 開始;但畫面同時顯示「出廠模型在開發時已經試了 37 個設定(v2 實驗登記簿,截至 2026-10-27)」。這個「設定」是登記簿的定義,和使用者的評分雜湊不同,畫面分開說明,不加總。

### 4.2 開發集與 holdout
- 切分沿用 `lab/research/splits.py`(`HOLDOUT_START = 2024-10-01`,約最近 24 個月),**不另設**。
- 模型工作台的回測只顯示開發集。
- holdout:每個模型族只能看一次,看之前畫面要確認;紀錄寫進 `private/models/holdout_log.jsonl`(模型族、評分雜湊、時間、結果)。看過之後該模型族任何新版本的 holdout 標「已看過,不是乾淨的樣本外」。
- 出廠模型的 holdout 仍然只走 `scripts/holdout.py` 與 `docs/holdout 評估日誌.md`,和使用者的紀錄分開。

### 4.3 比較與標示
- 每次回測同時顯示:我的模型、出廠模型、隨機排序對照組(沿用 `evaluate.py` 的雜訊對照)。
- 主要指標沿用 `evaluate.py`:長期 12 個月重疊世代月 IC、短期 1 個月 IC,Newey–West + fixed-b 95% 區間。
- 區間包含 0 → 「沒有證實有效」;與出廠模型的配對差異區間包含 0 → 「和出廠模型沒有差別」。
- 沒有歷史資料、或指標全部無法回測 → 「未驗證」。

### 4.4 輸出字眼
- 出廠模型照現行(評等、短期訊號,依 `validated_pillars` 與 `us_ratings` 政策)。
- **我的模型只輸出分數、等級(A+ ~ F)、在觀察清單或股票池內的排名**,不輸出「買進 / 賣出 / 減碼」等字眼。因此使用者模型**不走**決策切點(`decision.py` 的 `long_term_quantile` 與 cutpoints 檢查),也不進模擬帳戶。
- 排名來源:單一股票報告頁顯示「在觀察清單內」的排名(用同一個模型即時算觀察清單);「在股票池內」的排名只在市場掃描結果與回測頁顯示。

## 5. 效能:原始值快取(M4)

- 回測拆成兩段:① 每個(股票, 判斷日)抽出全部基礎變數的原始值 → 存 `OUT_DIR/bt_pit/raw_{tw,us}.sqlite`(慢,只跟資料版本有關);② 依模型打分、算 IC(快)。
- 估值(DCF 蒙地卡羅)只在 ① 算一次,公平價空間當成基礎變數。這也是 L4 估值方法權重延後的原因。
- 快取要存 §3.4 的全部變數(含輔助變數與 regime 分數),只靠快取就能重現長期與短期分數。
- 驗收:用出廠模型從快取打分,結果與完整 `backtest_pit` 逐筆相同;改一次權重重算在 10 秒內(台股 PIT 50 全期)。
