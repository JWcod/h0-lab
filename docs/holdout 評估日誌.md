# Holdout 評估日誌

用途:追蹤「holdout 被看了幾次」。每看一次就多一分過度配適的風險,所以每個階段最多 1 次,每次都要記在這裡。

**切分規則**(v2,2026-10-15 定案;程式在 `lab/research/splits.py`)
- 單一邊界 2024-10-01:這天以後的股價對所有預測期都是 holdout。
- holdout:判斷日 ≥ 2024-10-01。
- 開發集:結果視窗的最後一個**交易日** < 2024-10-01;跨過邊界的判斷剔除(階段 0 的 `metrics.py` 用日曆月,Verifier 指出會漏掉少數跨界判斷,影響約 0.5 個百分點;v1.1 基準數字保留原樣不改)。
- 為什麼不採計畫 Q1(b)「短期用 2025-10 起當 holdout」:短期的開發集會用到 2024-10 ~ 2025-09 的股價,那正是長期評等的 holdout,兩者共用面向,等於間接偷看。
- holdout 只能用 `scripts/holdout.py` 計算(自動在下表加一筆;同一個設定 hash 不重複計次)。
- 12 個月評等在 holdout 只有約 1 個獨立期間,只能當健全度檢查;閘門以 IC 為主(長期用重疊世代月 IC + Newey–West,見 `docs/架構.md` §3.1)。
- 真正乾淨的樣本外資料只有往後才發生的資料(復盤快照、模擬交易)。2021 年以前雖然 v1 / v1.1 設計時沒看過,但設計模型的 LLM 本身知道那段行情,只能算「較乾淨」。
